# EF Core 批量写与分表缓存修复

范围：保留上一轮评估第 3、4、5 项；用户随后要求撤回第 6 项组件拆分。保留 net8/net9/net10/net11 和现有仓储方法签名。

- 批量更新依据 EF 模型构建强类型属性表达式，先验证全部字段和值，保留租户过滤。
- 批量写入口确保主库；连接已打开或事务存在时不得跨库切换。提供显式写事务入口，Commit 仅保存跟踪变更。
- 分表迁移按上下文、Provider、主库连接指纹、后缀隔离；同键互斥、不同键独立，成功后缓存、失败可重试。
- 维持单一 Girvs.EntityFrameworkCore 组件，迁移生成器、Check、Tools/Design 依赖均恢复原位置与声明，不要求消费端新增设计时包或注册入口。
- 测试实际执行临时 SQLite 的关系数据库操作；MySQL/SQL Server 保留 SQL 生成检查，不冒充真实服务器验收。
- 不执行生产数据库变更，不包含 SQL Server 兼容级别、启动迁移策略及迁移 HTTP 端点整改。
