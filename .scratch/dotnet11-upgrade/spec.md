# 新增 .NET 11 与 EF Core 11 支持

Status: ready-for-agent

升级范围、依赖策略与测试边界均已由用户确认；根据用户对任务拆分的反馈排除容器示例。正式本地任务按依赖顺序记录。

## 问题陈述

Girvs 目前未声明 .NET 11 目标，EF Core 及多个模块按旧目标框架选择依赖。仅修改共享目标框架不能保证数据库提供程序、测试和示例编排在 .NET 11 下可用。现有使用方同时需要继续使用原目标框架。

## 解决方案

在保留各模块现有目标支持的基础上新增 .NET 11 支持。新增目标同步采用 EF Core 11，MySQL 提供程序使用经过兼容性验证的 Microting 11。库、测试、主示例服务、网关和 AppHost 纳入适配与验证，以可复现的完整使用链路验收。

## 用户故事

1. 作为框架使用方，我希望可以选择 .NET 11 目标资产，以便使用新运行时及对应依赖。
2. 作为现有使用方，我希望原目标框架及其依赖仍然可用，以便按自身节奏升级。
3. 作为数据库使用方，我希望 .NET 11 目标采用 EF Core 11，以便统一数据库访问栈。
4. 作为 MySQL 使用方，我希望通过 Microting 11 完成现有数据访问，以便沿用 Girvs 的配置与仓储接口。
5. 作为 SQL Server 使用方，我希望原有数据访问行为在 EF Core 11 下继续可用，以便升级不破坏现有业务。
6. 作为应用开发者，我希望查询、写入、延迟加载及分表相关行为得到验证，以便升级后保持数据访问语义。
7. 作为数据库维护者，我希望建表、迁移及迁移历史表行为得到验证，以便识别提供程序变化带来的影响。
8. 作为服务开发者，我希望 OpenAPI 和动态接口在 .NET 11 下保持现有调用方式，以便客户端继续调用。
9. 作为维护者，我希望现有测试同时覆盖 .NET 10 和 .NET 11，以便及时发现跨目标回归。
10. 作为示例使用者，我希望服务、网关和 AppHost 可以运行 .NET 11 验证链路，以便直接复现升级后的行为。
11. 作为维护者，我希望升级结果记录依赖组合、验证命令及实际结果，以便后续复现和排查。

## 实现决定

- 核心库在现有 .NET 8、9、10 目标之外增加 .NET 11；覆盖共享目标设置的模块按各自现有集合追加新目标。
- 旧目标的依赖继续分别选择；新增 .NET 11 分支不会将 EF Core 11 依赖引入旧分支。
- .NET 11 分支统一选择相互兼容的 Microsoft EF Core 11 组件和 Microting 11；接受 Microting 预发布候选，但不将依赖解析成功等同于运行兼容。
- Microting 11.0.0-preview.1 是此前查到的候选，最终组合在实施时核验并明确锁定；不能静默降为 EF Core 10 或移除 MySQL 功能。
- 构建 SDK 使用能够编译新增目标的 .NET 11 SDK，保留与任务无关的现有设置。
- 为按目标条件声明依赖的模块补齐 .NET 11 分支，优先保持现有公共接口和配置结构。
- OpenAPI、日志、消息总线、服务治理及其他传递依赖一并核查，按验证结果实施必要适配。
- 现有测试项目增加 .NET 11 执行覆盖，保留现有 .NET 10 测试。
- 主示例服务、网关和 AppHost 提供可复现的 .NET 11 运行路径，同时保留现有目标支持；AppHost 项目引用、启动目标和发布命令应明确目标框架。
- 共享示例配置变动应避免将容器示例隐式纳入新增目标；不调整其项目目标、Dockerfile 或容器发布方式。
- 不要求 Aspire 等第三方组件的主版本号与 .NET 对齐；根据其实际支持和验证结果选择版本。
- 发现候选依赖不兼容时记录实际阻碍，不将未通过的链路标为完成。

## 测试决定

优先通过已有公共入口验证外部行为，沿用现有 xUnit、服务治理、Hosting、网关与示例测试。仅在现有测试不能覆盖新旧目标行为差异时补充必要用例。

### 第一层：目标资产与回归

- 建立修改前的还原、构建和测试基线，区分原有问题与本次新增问题。
- 验证所有库原目标及新增目标的还原、构建和打包；检查包内目标资产及依赖组。
- 对现有测试执行 .NET 10 和 .NET 11 两条路径，修复本次升级引入的失败。
- 检查 OpenAPI 文档生成及已有 HTTP 契约，避免编译通过但接口描述失效。

### 第二层：实际数据库行为

- 通过 Girvs 的数据库配置、DbContext 和仓储公共入口验证 EF Core 11，与原 EF Core 10 路径比较可观察行为。
- 在临时隔离的 MySQL 数据库验证查询、写入、异步保存、延迟加载、分表及迁移历史表行为；仅对项目实际支持并使用的功能断言。
- 验证现有 SQL Server 提供程序的数据访问和建表、迁移路径。
- 覆盖关键边界：空查询结果、无待应用迁移或空迁移集合，以及现有 SQL 拦截器处理的特殊索引标识符。
- 数据库集成验证使用实际提供程序，不以 InMemory 测试替代关系数据库验收；测试库为可销毁的临时资源。

### 第三层：示例与编排链路

- 运行 AppHost 编排的 .NET 11 服务与网关，检查启动、健康检查、路由及示例服务间调用。
- 沿用现有 Hosting 和网关行为测试，检查升级后资源连接配置与服务发现行为。
- 验证文档中的显式目标框架构建、发布和运行命令可复现。
- 确认现有 .NET 10 验证路径仍可用。

## 范围之外

- 移除任何现有目标框架支持。
- 容器示例的目标框架升级、Dockerfile 调整、镜像构建及运行验收。
- 引入与升级无关的业务功能、公共 API 重构或数据库架构变更。
- 操作生产数据库、发布 NuGet 包或实际部署到生产环境。

## 补充说明

- 上述范围、EF Core 策略及三层测试边界已由用户确认；容器示例随后由用户明确移出范围。
- 本规格不是验证结果。目前尚未执行升级后的构建、测试、数据库或示例编排验收。
- 本地任务分为五项：基础支持、EF Core 11、其余模块、示例与 AppHost、最终验收。
