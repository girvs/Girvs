# 流程防护支持整段路径模板

下游接口常在路径中包含资源标识，例如 `/orders/42/confirm`。线性步骤和参数化流程接口池的 `Path` 都可使用整段 `{param}` 来匹配一个非空路径段。网关先匹配静态路径，再匹配同一 HTTP 方法、同段数的模板，以确定唯一受保护接口。路径参数值只参与匹配，前置参数和业务标识仍从各自的请求头读取。

## Considered Options

- 为每个资源标识配置静态路径。该方式需要预知所有资源标识，难以覆盖动态创建的资源。
- 支持完整的 ASP.NET Core 路由模板语法。约束、可选段和通配符会扩大语法范围，并使启动期判定两个模板是否可能命中同一请求更复杂。
- 按声明顺序或模板具体程度处理重叠。请求归属会受配置顺序或排序规则影响。启动期拒绝重叠，使更改声明顺序后请求仍命中同一接口。

## Consequences

- 路径从 `/` 开始，配置允许一个尾斜杠，拒绝空段以及 `*`、`?`、`#`。参数名符合 `[A-Za-z_][A-Za-z0-9_]*`，在模板内忽略大小写唯一。
- 同一方法下，静态路径可与模板并存，例如 `/orders/create` 优先命中静态步骤，`/orders/42` 命中 `/orders/{id}`。静态路径重复仍会报错。
- 同一方法、同段数的两个模板，只有在至少一个对应段位的字面量忽略大小写后不等时才可并存。启动期会区分重复、同形异名及交叉重叠，并为交叉重叠给出见证路径。例如 `/orders/export/items` 同时匹配 `/orders/{id}/items` 和 `/orders/export/{type}`。
- 运行期先查静态字典，再遍历对应方法和段数的模板。模板按段比较，不提取参数值。纯静态配置不分配模板索引。
